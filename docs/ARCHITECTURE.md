# ITSDM Architecture

## Core stack
- SPFx 1.23.x web part (SharePoint Online), Node 22
- React 17.0.1 UI layer, Fluent UI v8
- PnPjs for SharePoint access
- TypeScript, no extra runtime dependencies (charts are drawn as SVG)

## Layers
1. **Presentation** (`src/components`): one screen per tab (Dashboard, Ideas, Initiatives, Projects, Actions, Governance, Notes, Import, Help).
   - `shared/EntityScreen` is the generic list screen: command bar, search, status filter, "show closed", sorting, create/edit panel, details, archive, delete with confirmation, CSV export/import and inline status change. Ideas, Initiatives, Projects, Actions, Risks, Decisions, Lessons, Reviews, Notes and Meetings configure it; they do not repeat it.
   - `shared/HubData` loads every list once for the whole web part and shares it through context, so tabs do not refetch and a change in one tab shows up in the others.
   - `shared/DateField`, `UserField`, `LinkField` are the form inputs (calendar, people search, link picker).
2. **Hooks** (`src/hooks`): `useListItems` loads, creates, updates and removes items of a list, exposing errors and rethrowing write failures so a form never closes on a failed save.
3. **Services** (`src/services`): `SharePointService` (PnPjs: paging, create/update/delete, user search, version history). `PlannerService`, `GraphService` and `PowerAutomateService` are scaffolding only.
4. **Rules** (`src/rules`): pure, UI-independent and unit-tested.
   - `businessRules`, `transitions`: due dates, risk, allowed status changes.
   - `validation`: form validation (returns translation keys).
   - `dates`, `ids`, `csv`, `tableView`: date handling without timezone shifts, readable ids, CSV, search/filter/sort.
   - `transcriptImport`, `transcriptCommit`, `importPrompt`: the import from a meeting (see `IMPORTAR_REUNIONES.md`).
   - `governance`: risk score and level, and the status rules of risks, decisions, lessons and reviews.
   - `approvals`, `approvalMessage`: approval rules as data, the gate that blocks a protected change, and the email/Teams drafts (see `APROBACIONES.md`).
5. **Entities** (`src/entities`): the payload each list receives and the columns requested from it, shared by forms, CSV import and meeting import so all write the same shape.
6. **i18n** (`src/i18n`): English and Spanish dictionaries with typed lookup. The language follows the user's SharePoint language or is forced from the web part properties. A test checks both dictionaries have the same keys and that no key used in code is missing.

## Layout
`supportsFullBleed` is declared in the web part manifest, so it can be placed in a full-width section. The root fills the width it is given; tables scroll inside their own container, grids reorganise by width, and panels use the available space.

## Integrations
- Current: SharePoint Online lists (via the signed-in user, no custom auth).
- Not implemented (see `ROADMAP.md`): Planner, Power Automate, Microsoft Graph.
- The app never calls an AI service. The text an AI produced from a transcript is pasted by the user and interpreted locally.

## Deployment model
`.sppkg` through the App Catalog. The package carries a feature (`elements.xml` plus one list schema per list, generated by `scripts/generate-assets.js`) so adding the app to a site creates the lists and sample items.

## Quality
`npm test` runs lint, compilation and fourteen test groups, including component tests of the Import flow and the list screens in a simulated browser (jsdom). GitHub Actions (`.github/workflows/ci.yml`) runs the same plus packaging on every push.
